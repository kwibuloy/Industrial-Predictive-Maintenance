# Modelling rules and conventions

The agreed design and the open questions are in [decisions.md](decisions.md).

## Rules that must hold

- **FDR = FP / (FP + TP) = 1 - precision**, computed on stage 1 alarms. If a threshold
  raises no alarms, FDR is undefined: report "no alarms", never 0.
- **The test set is used once**, for the final report. Never tune a threshold, pick a
  model or choose features by looking at test results.
- **Leakage.** `TWF`, `HDF`, `PWF`, `OSF`, `RNF` are labels and must never be stage 1
  features. `UDI` and `Product ID` are identifiers; drop them. Fit scalers, encoders and
  any resampling inside a `Pipeline` or within each CV fold, never before the split.
- Class weights (`scale_pos_weight`, `class_weight`) distort predicted probabilities, so
  tune the threshold after they are set, on the same configuration.
- `data/raw/` is read-only. Derived data goes to `data/processed/`.
- Fix `random_state` everywhere. Results must reproduce from a clean run.

## Column names

Rename to snake_case on load; XGBoost rejects feature names containing `[` or `]`.

| Raw | Renamed |
|---|---|
| `Air temperature [K]` | `air_temp_k` |
| `Process temperature [K]` | `process_temp_k` |
| `Rotational speed [rpm]` | `rot_speed_rpm` |
| `Torque [Nm]` | `torque_nm` |
| `Tool wear [min]` | `tool_wear_min` |
| `Machine failure` | `machine_failure` |
| `Product ID`, `Type` | `product_id`, `type` |

## Layout

```
data/raw/            original CSV (read-only)
data/processed/      derived tables, split indices, out-of-fold predictions
src/pdm/             config, data, features, metrics, plotting (shared)
                     eda, train, evaluate, rul, report (each runs with python -m)
notebooks/           predictive_maintenance.ipynb (imports pdm, no logic of its own)
models/              saved pipelines (joblib)
reports/figures/     plots
reports/metrics/     JSON and CSV results
reports/summary.md   generated by pdm.report; never edit by hand
tests/               pytest
```

## Pipeline order

```
.venv\Scripts\python.exe -m pdm.eda        # profile + lead-indicator correlation
.venv\Scripts\python.exe -m pdm.train      # stage 1 and 2 models, out-of-fold predictions
.venv\Scripts\python.exe -m pdm.evaluate   # thresholds, test report (needs train)
.venv\Scripts\python.exe -m pdm.rul        # remaining tool life
.venv\Scripts\python.exe -m pdm.report     # reports/summary.md (needs all of the above)
```

`data/processed/split.csv` is created once and reused. If it is deleted or changed,
rerun `pdm.train` before `pdm.evaluate`.

Numbers in the notebook and `reports/summary.md` come from `pdm.report` reading
`reports/metrics/`. The headline figures in `README.md` are typed in; update them from
`reports/summary.md` whenever results change.

## Reporting the cap

Say the 5% cap is "met" only when the whole 95% interval of test FDR is under it
(`metrics.cap_verdict`). An estimate under the cap with an interval above it is "not
demonstrable". Quote test figures, not the development out-of-fold ones: those are
optimistic because the threshold was chosen on them.

## Tests

A Stop hook runs `pytest -m "not slow"` at the end of every turn, so default tests must
finish in seconds: use small synthetic frames, not real training runs. Mark anything
that fits a real model with `@pytest.mark.slow`. The FDR and threshold-selection
functions need unit tests with hand-computed expected values.
